How the seal works

1. Read original bytes

Files are read in-browser; the original file is not modified.

2. Calculate SHA-256

A cryptographic digest acts as a file fingerprint.

3. Link the log

Each record includes the previous record's chain hash.

A hash proves only that bytes match a recorded digest. It does not prove source, authorship, original creation time or authenticity. This demo has no trusted timestamp authority, external signature, or durable encrypted storage.

Privacy & Settings

Prototype controls for this browser session. A real deployment needs audited security engineering before handling sensitive material.

Local session only

Safety appearance

Quick exit switches to a neutral notes screen. It does not erase browser history, downloads, memory, or network traces.

A decoy PIN and hidden vault can create a false sense of security. They are not implemented here. Do not rely on this demo to protect you from someone with device access.

Delete session data

Evidence records, case details, timeline entries and tracker entries are held in page memory only. Reloading or closing the page clears them.

Security limitations

  • No authentication, PIN lock, server, database or encrypted persistent vault.
  • No external trusted timestamp, certificate signing or public QR verification.
  • No live AI provider, OCR engine, language translation or automated legal analysis.
  • No portal, police, platform or case-status integration.
  • Do not upload real intimate imagery or sensitive victim data to this prototype.
